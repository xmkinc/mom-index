## Implemented

- Added `mom_index/collectors/xhs_import.py` exposing `import_xhs_file(path) -> SourceResult`.
  - Accepts JSON arrays, per-sector JSON maps (`{sector: [record, ...]}`), and JSONL (one record per line; extension `.jsonl` selects JSONL mode, otherwise JSON).
  - Accepts only the seven sanitized public fields: `id`, `title`, `content`, `url`, `sector`, `published_at`, `collected_at`. Unknown fields are rejected explicitly per record.
  - URLs must match `^https://(?:www\.)?xiaohongshu\.com/`; sectors must be the configured four (`nasdaq`, `gold`, `cpo`, `semiconductor`).
  - `published_at` may be `null` or a timezone-aware ISO timestamp; `collected_at` must be a timezone-aware ISO timestamp (naive timestamps are rejected).
  - **Fail closed**: any record carrying a banned identity/credential/profile/session key (e.g. `cookie`, `cookies`, `author`, `author_id`, `followers`, `follower_count`, `session`, `session_token`, `access_token`, `api_key`, `authorization`, `password`, `secret`, `token`, `browser_profile`, `nickname`, `display_name`, …) aborts the entire import and returns `SourceResult(mode="unavailable")` with zero posts — previously-validated records are discarded.
  - **Fail closed**: secret-like values (credential assignments, bearer tokens, `sk-…`, `gh[p|s]_…`, `AKIA…`) in `id`/`title`/`content`/`url` also abort the entire import.
  - Invalid individual records (bad URL, bad sector, missing required field, unknown non-banned field, malformed/naive timestamp, oversized field, non-object) are rejected **explicitly** with a per-record error message; remaining valid records are still imported.
  - Zero valid records → `SourceResult(mode="unavailable")`.
  - Success → `SourceResult(mode="imported")` with `collected_at = isoformat_utc()` (import time), per-record `collected_at` preserved from the file, and `platform="xiaohongshu"` added to each normalized post for the classifier.
  - Key normalization is camelCase/kebab-case aware (mirrors `validation.py`), so `browserProfile`/`browser-profile` are caught as `browser_profile`.
  - Does not read browser profiles, cookies, credentials, or network resources; not added to `get_public_collectors()`; no public collector or workflow modified.

- Added `tests/test_xhs_import.py` with five test classes:
  - `TestSanitizedImport`: JSON array, sector map, JSONL, blank-line skipping, `published_at: null`, all four sectors.
  - `TestFailClosed`: parametrized banned identity/credential keys (16 fields), fail-closed discards prior valid records, secret-like value (credential assignment) aborts, `sk-…` token pattern aborts, `XhsImportError` is raisable.
  - `TestZeroValidRecords`: empty JSON array, empty/whitespace JSONL, all-records-invalid.
  - `TestSchemaRejections`: bad URL (others kept), missing required field, invalid sector, non-XHS HTTPS, HTTP URL, naive timestamp, malformed timestamp, unknown field, oversized title, empty title, non-object record, sectorMap sector mismatch, sectorMap unknown key.
  - `TestFileErrors`: missing file, invalid JSON, invalid JSONL line, non-array/non-map JSON.

- **Tests not executed.** The implementation is believed correct by manual review, but the integrator MUST run `python -m pytest -q tests/test_xhs_import.py` (and the full suite) before merge. Any failures must be returned to this worker or fixed in integration.
- **No commit created.** The two files are uncommitted in the worktree. The integrator must create the atomic commit with `Task`/`Agent`/`Spec` trailers.
- **HEAD not verified.** The integrator must confirm the worktree HEAD matches the immutable dispatch base `d9687c5f418cbd7f4f64b065515471966fc31444`.
- **JSONL parse-error policy.** A malformed JSONL line (non-JSON) causes the whole file to return `unavailable`, rather than per-record rejection. This treats an undecodable line as a file-integrity failure (safer). A record that decodes but fails schema validation is still rejected per-record. If the integrator prefers per-line leniency, `_decode_jsonl` would need adjustment.
- **Secret scan scope.** Secret-like values are scanned only in the free-text fields `id`, `title`, `content`, `url`. Structured fields (`published_at`, `collected_at`, `sector`) are type-constrained; a secret placed there is rejected as a schema violation (per-record), not fail-closed. This is a deliberate, defensible boundary; broaden if the integrator disagrees.
- **`build_dashboard` eligibility.** `cli.build_dashboard` currently collects only `live`/`simulated` results; it does not yet include `imported`. CLI wiring for `--xhs-import` is out of T-003 scope (deferred to the CLI task). The importer is usable directly via `import_xhs_file` and produces a valid `imported` `SourceResult`.
- The importer is deliberately absent from `get_public_collectors()`; public Actions remain Guba-only and unauthenticated, per the charter and design.
